# Catalog Service

Модель опубликованных карточек Student Discounts. Java 25, Spring Boot 4.1.2, PostgreSQL 17 + PostGIS 3.5, Spring JDBC, Flyway.

## Что реализовано

- `Category`: справочник с постоянным кодом, названием и признаком активности.
- `Place`: название, город, адрес, координаты, категория и часовой пояс. `organization_id` зарезервирован и при создании не заполняется.
- `Offer`: условия, тип и размер скидки, источник, сроки, дата проверки, статус и ссылка на одобренную версию заявки.
- `ScheduleInterval`: день недели и местный интервал действия. Поддерживается `24:00`, соседние интервалы разрешены, пересечения запрещены.
- `DiscountCard`: место вместе со скидкой; проверка действия скидки на заданный момент учитывает часовой пояс места.
- Сохранение и чтение через JDBC, географические координаты PostGIS, миграции и ограничения в БД.
- Публикация одобренного снимка одной транзакцией, повторная обработка без дублей, защита от устаревших изменений и outbox-запись `OfferPublished`.

Модель заявок, проверка черновиков и отправки, UUIDv7 и неизменяемые версии уже реализованы Львом в `Student-Discounts/submission`, PR #1. Здесь нет второй реализации этих механизмов. Основа таблиц каталога — `Student-Discounts/docs`, PR #17, коммит `b6fb016`; существующая SQL-схема перенесена в V1 без изменений, дополнения находятся в V2.

## Сборка и тесты

Нужны JDK 25 и работающий Docker. Тесты запускают настоящий PostgreSQL 17 с PostGIS 3.5 через Testcontainers; H2 и пропуск проверок БД не используются.

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@25/libexec/openjdk.jdk/Contents/Home
./gradlew build
```

Путь `JAVA_HOME` выше относится к Homebrew на Apple Silicon. На другой машине укажите установленный JDK 25. Gradle Wrapper фиксирует версию сборщика.

Для установленной Colima:

```bash
export DOCKER_HOST="unix://$HOME/.colima/sd-model/docker.sock"
export TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock
./gradlew build
```

Образ `postgis/postgis:17-3.5` запускается как `linux/amd64`; на ARM нужен Docker с эмуляцией amd64. Ночной интервал хранится двумя строками, например пятница 22:00–24:00 и суббота 00:00–02:00.

## Локальный запуск

```bash
docker compose up -d --wait
./gradlew bootRun --args='--spring.profiles.active=local'
```

По умолчанию приложение слушает `127.0.0.1:8082`, БД — `127.0.0.1:5434`. Локальные учётные данные находятся только в `application-local.yml` и Compose. Вне локального профиля обязательны `CATALOG_DB_URL`, `CATALOG_DB_USER`, `CATALOG_DB_PASSWORD`.

База изначально пустая. Справочник категорий заполняется миграциями данных или доверенным кодом через `CatalogRepository.saveCategory`; тестовые категории не добавляются в рабочую базу автоматически.

## Контракт с Submission Service

Три внутренних read-only маршрута соответствуют `BusinessClients` из `submission`, коммит `270180a`:

| Маршрут | Ответ |
|---|---|
| `GET /catalog/v1/categories/{code}` | `code`, `name`, `sortOrder`, `isActive` |
| `GET /catalog/v1/places/{id}` | `id`, `name`, `city`, `addressLine`, `location.lat/lon`, `categoryCode`, `timezone`, `rowVersion` |
| `GET /catalog/v1/offers/{id}` | `id`, `placeId`, `status`, `rowVersion`, `payload` |

Неизвестный идентификатор возвращает 404, неправильный UUID — 400. Для подключения Submission укажите `SD_SUBMISSION_CATALOG_BASE_URL=http://localhost:8082`.

Это внутренние маршруты: снимок скидки содержит источник и ссылки на подтверждения, включая `source.note`. Не подключайте их к публичному API Gateway. Они слушают loopback и не предоставляют операций записи. Публичная карточка с удалением закрытых полей и межсервисная аутентификация должны быть добавлены при подключении публичного API.

`payload` содержит одно предложение с его текущим id и только относящимися к нему вложениями. Индексы вложений пересчитываются в 0. Место собирается из текущей записи, поэтому правка места не оставляет старый адрес в снимках соседних скидок.

## Запись одобренных данных

Доверенный прикладной код вызывает `CatalogPublicationService.publish(ReviewedSubmission)`. Вход — уже проверенная неизменяемая версия с типом `NEW_PLACE`, `NEW_OFFER` или `CHANGE`, номером и id версии, разрешённым часовым поясом и текущей версией строки заявки после одобрения. Для такого вызова нет публичного HTTP-эндпоинта.

- `NEW_PLACE` создаёт место и 1–5 скидок. Все новые id генерирует каталог в формате UUIDv7.
- `NEW_OFFER` добавляет 1–5 скидок к существующему месту, не изменяя его данные.
- `CHANGE` обновляет одну скидку при совпадении `baseOfferRowVersion`. Снятую скидку этот вызов не восстанавливает.
- Изменение самого места дополнительно требует `basePlaceRowVersion`, иначе возвращается `PLACE_VERSION_REQUIRED`. Сейчас Submission хранит только версию скидки: передачу версии места нужно согласовать перед подключением таких изменений. Это предотвращает незаметное затирание правок соседних карточек.
- Неактивная категория и уже истёкший срок блокируют новую публикацию. Если источника нет, у предложения должно быть подтверждение; проверку владельца и безопасности файла выполняют Submission и Media до вызова.
- Повтор той же версии возвращает прежние id; другое содержимое под тем же id отклоняется. Место, скидки, расписание, снимки, результат публикации и outbox записываются одной транзакцией.

`catalog_outbox` сохраняет событие по действующему контракту `submission.workflow.v1`: `producer=catalog`, `eventType=OfferPublished`, `submissionId`, `versionId`, `versionNo`, `expectedRowVersion`, `offerIds`. Поле `expectedRowVersion` относится к заявке в состоянии `APPROVED`, не к скидке.

В этой работе реализованы модель и транзакционная запись. Приём одобрений из Kafka, доставка outbox, события для индекса поиска, геокодер и публичный API не подключены. Их нельзя считать работающим сквозным сценарием. Транспортный обработчик должен проверить одобрение и взять сохранённую проверенную версию; нельзя вызывать публикацию с произвольным пользовательским JSON.

## Проверки

Тесты покрывают модель, сохранение/чтение, PostGIS, полночь, ограничения БД, несколько скидок и вложения, повторы и одновременную публикацию, откат транзакции, конфликт версий, HTTP-контракт и outbox. Результаты находятся в `build/reports/tests/test/index.html`.

Проверено 6 ноября 2026 года:

- `./gradlew javaFormat build`: 24 теста, 0 ошибок, 0 пропусков; собран `build/libs/catalog-service.jar`.
- JAR запущен отдельно на чистой PostgreSQL 17.5 / PostGIS 3.5.2; Flyway применил обе миграции, health и внутренний API ответили успешно.
- Настоящий `BusinessClients` из Submission прочитал категорию, место и скидку из этого JAR. Возвращённый снимок принят настоящим `PayloadValidation` из Submission.
- Образцы `build/contract-samples/payload.json` и `offer-published.json`, полученные тестами из БД, проверены по JSON Schema из Submission `270180a`.

В исходном Submission отдельно прошли 84 модульных теста. Его полный интеграционный прогон в Colima не прошёл из-за `Connection refused` при подключении к опубликованным PostgreSQL-портам. Это не считается успешной проверкой всех интеграционных сценариев Submission; код коллеги не изменялся.
